Relationships Overview

1:N - Customer to Order
One customer can have multiple orders. Accessed via customer.order_set.all()
1:N - Product to Order
One product can be ordered multiple times. Order references Product via Foreign Key.
Cascade Behavior
Both customer and product foreign keys use SET_NULL - orders survive if customer/product is deleted.

📦 ORDER Entity

Field Name Data Type Constraints Description
id Integer PRIMARY KEY, AUTO Unique order identifier

product Integer FOREIGN KEY, SET_NULL Reference to Product (1:N)
date_created DateTime AUTO, NULL Order creation timestamp
status String(200) CHOICE: Pending, Out for delivery, Delivered Current order status

Cardinality & Integrity Constraints

One-to-Many (1:N)

Customer ↔ Order: One customer can place multiple orders, but each order belongs to exactly one customer.

Product ↔ Order: One product can be ordered multiple times by different customers.

Foreign Key Constraints

SET_NULL Behavior: If a customer or product is deleted, related orders remain but the FK is set to NULL.

Referential Integrity: Order can only reference existing Customer/Product or NULL.

Primary Keys

Auto-increment ID: Each entity has an auto-incrementing integer primary key (id) starting from 1.

Uniqueness: Ensures no duplicate records within each entity table.
